# WinDjView Extended

[![Сборка](https://github.com/sklart/WinDjView-Extended/actions/workflows/build.yml/badge.svg)](https://github.com/sklart/WinDjView-Extended/actions/workflows/build.yml)

**WinDjView Extended** — быстрый и компактный просмотрщик документов DjVu для Windows, написанный на C++ с использованием MFC.

Этот репозиторий является развиваемым продолжением **WinDjView Extended 4.1** от N.M.E., который, в свою очередь, основан на оригинальном **WinDjView** Эндрю Жежеруна.

Цель проекта — сохранить сильные стороны классического WinDjView:

* высокую скорость запуска;
* небольшой размер;
* низкое потребление ресурсов;
* нативный интерфейс Windows;
* удобную работу с большими DjVu-документами;

и одновременно устранить ограничения устаревшей кодовой базы:

* модернизировать библиотеки декодирования;
* обеспечить полноценную сборку x64;
* улучшить работу на современных мониторах;
* повысить устойчивость к повреждённым документам;
* сделать проект удобным для дальнейшей разработки и сопровождения.

---

# Происхождение проекта

История проекта:

* **WinDjView** — оригинальный просмотрщик DjVu, созданный Эндрю Жежеруном;
* **WinDjView Extended** — расширенная версия, развивавшаяся N.M.E. (`nme3001`) и опубликованная на SourceForge;
* **данный репозиторий** — основан на исходном коде WinDjView Extended 4.1 и содержит дальнейшую модернизацию и исправления.

Исходные проекты:

* [WinDjView Extended на SourceForge](https://sourceforge.net/projects/windjviewextended/)
* [Оригинальный WinDjView](https://windjview.sourceforge.io/)

Первоначальный импорт исходников WinDjView Extended 4.1 в этот репозиторий выполнен коммитом `549daaa`.

# Что даёт обновлённая версия на практике

По сравнению с исходным WinDjView Extended 4.1 текущая версия не просто собирается современными инструментами, но даёт ряд практических преимуществ.

## Для обычного пользователя

* лучше работает на современных мониторах с масштабированием 125%, 150%, 200% и выше;
* стабильнее работает с большими и повреждёнными DjVu-файлами;
* меньше вероятность аварийного завершения из-за некорректной структуры документа;
* исправлены проблемы, проявлявшиеся только в 64-разрядной версии;
* улучшена обработка печати и нестандартных драйверов принтеров;
* современная JPEG-библиотека потенциально ускоряет декодирование JPEG-составляющих DjVu;
* доступна полноценная x64-сборка;
* сохранён лёгкий нативный интерфейс без тяжёлых дополнительных фреймворков.

## Для пользователей больших архивов DjVu

Обновление особенно полезно при работе с:

* отсканированными книгами;
* архивными фондами;
* технической документацией;
* большими многостраничными файлами;
* документами, созданными различными версиями DjVuLibre;
* старыми DjVu-файлами с нестандартными или частично повреждёнными структурами.

Более строгая проверка внутренних данных снижает вероятность того, что один проблемный файл приведёт к падению всей программы.

## Для разработчиков

* проект можно собирать современным Visual Studio;
* поддерживаются Win32 и x64;
* есть Debug и Release;
* сборки автоматически проверяются через GitHub Actions;
* обновлены ключевые зависимости;
* исправлена часть опасного ручного управления ресурсами;
* код стал лучше подготовлен к дальнейшей модернизации.

# Непрерывная интеграция

В репозитории настроен GitHub Actions.

При каждом push и pull request выполняются:

* Debug Win32;
* Release Win32;
* Debug x64;
* Release x64.

Дополнительно проверяются:

* успешное создание `WinDjView.exe`;
* правильная архитектура PE-файла.

### Практическое преимущество

Любое изменение автоматически проверяется сразу в четырёх основных конфигурациях.

Это снижает вероятность ситуации, когда:

* исправление для x64 ломает Win32;
* Debug собирается, а Release — нет;
* разработчик случайно публикует бинарник неправильной архитектуры;
* изменение зависимости обнаруживается только перед релизом.

CI делает поддержку проекта значительно надёжнее.

# libjpeg-turbo 3.2.0

Старая библиотека **IJG JPEG 6b** заменена на **libjpeg-turbo 3.2.0**.

WinDjView продолжает использовать классический API libjpeg, необходимый DjVuLibre.

Интеграция поддерживает:

* статическую линковку;
* Win32;
* x64;
* Debug;
* Release;
* совместимый API/ABI libjpeg 6.2;
* SIMD-ускорение через NASM в официальных Release-сборках Win32 и x64;
* прямой вывод BGR в `GPixmap` без промежуточного PPM-буфера;
* меньше лишних копирований данных и промежуточной памяти;
* статическая линковка без `jpeg.dll` или `turbojpeg.dll`.
* отсутствие зависимости от внешней JPEG DLL.

### Практическое преимущество

JPEG используется внутри многих DjVu-документов для хранения фоновых и цветных слоёв.

Переход на libjpeg-turbo даёт:

* более современную и поддерживаемую реализацию JPEG;
* потенциально более быстрое декодирование;
* возможность аппаратно-оптимизированного SIMD-кода;
* полноценную поддержку x64;
* устранение зависимости от очень старого JPEG-кода.

Локальный тест проекта показывал примерно двукратное ускорение JPEG-декодирования при использовании SIMD, хотя реальный выигрыш зависит от документа, процессора и структуры DjVu.

Для пользователя это потенциально означает более быструю отрисовку цветных и сканированных страниц.

Подробнее: [docs/libjpeg-turbo.md](docs/libjpeg-turbo.md).

# Поддержка HiDPI

Добавлена улучшенная поддержка современных мониторов.

Реализованы:

* High-DPI Awareness;
* Per-Monitor DPI Awareness;
* обработка изменения DPI;
* корректировка окна при переносе между мониторами.

### Практическое преимущество

На современных ноутбуках и 4K-мониторах Windows часто использует масштабирование 125–200%.

Старые приложения при этом могут выглядеть:

* размытыми;
* слишком мелкими;
* неправильно масштабированными;
* с некорректными размерами отдельных элементов.

Обновлённый WinDjView лучше взаимодействует с системным масштабированием Windows.

Особенно заметно улучшение при:

* работе на 4K-мониторе;
* использовании ноутбука с высоким DPI;
* переносе окна между мониторами с разным масштабом.

# Полноценная поддержка x64

Исходный код содержал ряд предположений, характерных для 32-разрядных приложений.

Исправлены:

* преобразования указателей;
* преобразования индексов;
* обработка аннотаций;
* массовое удаление аннотаций;
* владение узлами дерева;
* работа потоков;
* операции печати;
* преобразования координат и размеров.

### Практическое преимущество

Речь идёт не просто о том, что программа теперь компилируется как x64.

Исправлены ошибки, которые могли проявляться только при 64-разрядной сборке:

* повреждение указателей;
* неправильные индексы;
* нестабильное удаление объектов;
* неожиданные сбои.

Пользователь получает нормальную нативную x64-версию, а не формально портированный 32-разрядный код.

Дополнительным преимуществом x64 является значительно большее виртуальное адресное пространство, что полезно при работе с очень большими документами и растровыми страницами.

# Безопасная обработка внешних ссылок

Внешние ссылки из DjVu теперь проверяются перед передачей Windows.

Разрешены схемы:

* `http`;
* `https`;
* `mailto`.

### Практическое преимущество

DjVu-файл является входными данными, которым нельзя полностью доверять.

Ограничение допустимых URI уменьшает вероятность запуска через ссылку:

* произвольных локальных файлов;
* нестандартных обработчиков Windows;
* потенциально опасных URI-схем.

Обычные веб-ссылки и электронная почта при этом продолжают работать.

Подробнее: [docs/security-hardening.md](docs/security-hardening.md).

Проект остаётся нативным Windows-приложением.

Интерфейс основан на:

* Win32;
* MFC.

Текущий код сохраняет ориентацию на Windows 7-era API.

Однако использование современного Visual Studio означает, что совместимость готового бинарного файла с Windows 7 необходимо дополнительно проверять на:

* Windows 7 x86;
* Windows 7 x64.

Совместимость с более старыми версиями Windows, которые могли поддерживаться историческим WinDjView Extended, не гарантируется.

# Лицензия

WinDjView Extended распространяется на условиях **GNU General Public License версии 2 или более поздней**.

Текст лицензии:

```text
src/license
```

Встроенный DjVuLibre также распространяется на условиях GPL-2.0-or-later.

libjpeg-turbo содержит собственные уведомления об авторских правах и лицензировании:

```text
src/third_party/libjpeg-turbo/
```

При распространении бинарных версий необходимо сохранять требуемые уведомления сторонних компонентов.
